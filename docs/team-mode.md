# 팀전 설계 (v3, 구현 완료) → 현재 이름 "방 만들기"

> 2026-11 변경: 이름이 **방 만들기**로 바뀌고 기존 1:1 온라인 모드는 삭제됨(1:1도 이 방에서). 모드 선택 다음에 [일반전 / 속기전] 단계가 추가됨 — 방장이 정한 시간 규칙(`TM.rule`)을 참가자도 따르고, 시계(`clock: {side, used}`)는 스냅샷에 실려 가며 시간 초과는 방장이 판정(`result.reason = 'time'`). 시계 규칙은 `team.js`의 `spend`/`budget`/`view`.
> 2026-11 추가: **무승부 제안 · 항복 투표** (방장이 진행·검증). 무승부 제안은 한 판에 한 사람당 2번(`snap.votes {id: n}`, 방장 승계 후에도 유지, 다 쓰면 버튼 비활성), 항복은 횟수 제한 없음.
> | 방향 | 메시지 | 방장 검증 |
> |---|---|---|
> | G→H | `{type:'vote-start', kind:'draw'\|'resign'}` | 대국 중, 진행 중 투표 없음; 무승부는 보낸 사람 팀 차례 + 남은 횟수 있을 때만 |
> | H→G | `{type:'vote', kind, from, ask:[ids], yes:[ids], ends}` | `ask`는 시작 때 한 번 고정(`TeamLogic.voteAsk`): 무승부 = 제안자 뺀 접속자 전원(양 팀), 항복 = 제안자의 접속 중 팀원. `ask` 중 `yes`에 없는 사람에게만 동의/거절 버튼. `ends` = 남은 ms. 모두에게 "동의 (yes+1)/(ask+1)" 표시(제안자는 동의로 셈) |
> | G→H | `{type:'vote-reply', ok}` | `ask`에 있고 아직 답 안 한 id만 유효; 거절 1번이면 취소 |
> | H→G | `{type:'vote', kind, from, cancelled:true, why, by}` | `why`: `refused`(by = 거절한 id) / `timeout` / `left`(제안자·상대 팀 이탈) / 없음(대국 종료, 성립 포함). 모두에게 판 아래 알림 "… — 게임이 계속됩니다!" |
> - `ask` 전원이 `yes`면 방장이 종료: 항복 = `result {winner, reason:'resign'}`, 무승부 = `{draw:true, reason:'agreed'}` (게스트 sanitizer 허용 reason: `wipe, time, resign, agreed`).
> - 투표 중 끊긴 사람은 `ask`에서 빠짐. 제안자가 끊기거나, 무승부인데 상대 팀 응답자가 모두 끊기면 취소(상대 동의 없는 무승부 방지). 혼자인 팀의 항복은 `ask = []` → 확인 창 후 바로 패배. 방장 승계 시 진행 중 투표는 사라짐.
> - "더 이상 둘 수가 없습니다" 안내는 각자 스냅샷 판으로 `TeamLogic.bestWindow`를 계산(메시지 추가 없음).
> 아래 본문 중 "1:1 온라인은 별도 모드로 유지", "자유룰/금수 없음"은 옛 내용 — 지금은 모든 모드에 한국식 금수 적용.

## 규칙
- 최대 4명, 2팀(흑/백), 팀당 1~2명. 같은 팀은 같은 색 돌. 자유룰(5목 이상), 렌주/금수 없음.
- **시작 조건**: 양 팀 모두 1명 이상이면 호스트가 언제든 시작 (4명 안 차도 됨). 1:1, 2:1, 2:2 모두 가능.
- **수순**: 팀이 흑→백→흑→백 교대. 팀 안에서는 접속 중인 팀원이 순서대로 돌아가며 둠 (흑A, 백A, 흑B, 백B …). 팀원이 1명이면 그 사람이 계속 둠.
- **이탈**: 팀원이 나가도 게임 계속. 나간 사람은 팀 내 순번에서 건너뜀. 같은 토큰으로 재접속하면 복귀.
- **패배**: 한 팀의 접속 인원이 0이 되면 그 팀 패배(상대 팀 승리, 전적 +1). 재접속 유예 10초 안에 아무도 못 돌아오면 확정. 유예 중 그 팀 차례면 대기.
- 승리/무승부/전적은 기존 `checkWin`, `scores[1|2]` 그대로 재사용.

## 데이터 모델 (호스트 권위)
```
players: [{id, name, team: 1|2, online}]   // id = 호스트 발급, 게스트 토큰과 매핑
turn: {team: 1|2, idx: {1: n, 2: n}}        // 팀별 로테이션 포인터
```
- 현재 차례 플레이어 = `players.filter(p => p.team===turn.team && p.online)[idx % len]`.
- 수 둔 뒤: 팀 전환 + 그 팀의 idx 유지, 방금 둔 팀 idx+1. 순수함수 `nextTurn(players, turn)`.
- `currentPlayer`(색)는 `turn.team`과 동일 → 기존 렌더링 코드 재사용.

## 토폴로지: 호스트 스타
- 호스트가 `zestmok-<CODE>` Peer, 게스트 최대 3명이 호스트에만 접속. TURN/CSP 변경 없음.
- 게스트는 `move`만 전송, 호스트가 (보낸 사람 == 현재 차례 플레이어, 범위, 빈 칸) 검증 후 `state` 브로드캐스트. 낙관 적용 없음.
- `token`(sessionStorage 랜덤값)으로 재접속 시 같은 플레이어 복구.

## 메시지
- G→H: `hello {name, token}` · `pick-team {team}` · `move {row,col}` · `restart-req` · `ping`
- H→G: `welcome {id}` · `lobby {players, started}` · `state {board, turn, lastPlaced, gameOver, winningCells, players}` · `full` · `rejected {reason}` · `ping`
- 시작 후 신규 입장은 `rejected`(토큰 없는 자는 불가). 게스트 간 직접 통신 없음.

## 로비 / 방 만들기
- **방 만들기**: 호스트가 흑/백 선택 → 해당 팀에 자동 배치.
- **참가**: 코드 입력 + 닉네임 → 입장하면 로비 화면에서 **팀 선택**(흑/백 카드 클릭). 팀 정원(2) 차면 비활성. 시작 전에는 자유롭게 변경 가능. 호스트도 팀 변경 가능.
- **인원 표시**: 로비 상단 `3/4`, 팀 카드에 닉네임 목록과 빈 자리. 게임 중에도 `conn-status`에 `접속 3/4`(시작 시 인원 기준 분모).
- **시작 버튼**: 호스트에게만 보임. 양 팀 1명 이상일 때 활성, 아니면 사유 표시("백팀에 최소 1명 필요"). 4/4이어도 자동 시작 안 함.
- 닉네임 12자 제한, `textContent`로만 렌더(XSS 방지).

## 일반화 / 리팩터
- 1:1 온라인은 "흑 1명 vs 백 1명" 케이스로 흡수 → **한 코드 경로** 유지(별도 모드 복붙 금지). 단 1:1의 즉시 입장 UX가 달라지므로(로비 거침) 모드 선택에서 "온라인 1:1"은 유지하되 내부적으로 `maxPerTeam=1`로 로비를 재사용하는 안을 권장.
- 변경 대상(1명 전제 변수): `conn`→호스트 `conns[id]`, `myOnlinePlayer`→`myId`/`myTeam`, `lastSeen`/`graceTimer`/`peerLost`→플레이어별, `isValidMove`의 `expected`→보낸 사람 검증.

## 연결 끊김 상세
- 플레이어별 하트비트. 끊김 → `online=false` → `lobby/state` 브로드캐스트(팀원 이탈 표시).
- 끊긴 사람 차례였다면 즉시 팀 내 다음 접속자로 넘김(팀에 접속자가 남아 있을 때).
- 호스트 이탈 → 입장 순서상 다음 접속자가 방장 승계(8초 내 못 열면 그다음 사람).

## 재시작
